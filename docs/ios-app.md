# The iOS app

The Client Hub iOS app is a native shell around the web dashboard. It is a
Capacitor app whose web view opens https://dashboard.socialupgrades.com, so
the app *is* the website's mobile layout, with the browser chrome removed and a
few native pieces added. Two consequences follow, and they are the point:

- **Deploying the website updates the app.** Every installed copy shows the new
  design or behaviour the next time it is opened. No App Store review, no app
  update.
- **Data is shared.** Same Supabase project, same logins, same row-level
  security. A change made on a laptop at work shows up on the phone within
  the dashboard's normal 15-second poll, and immediately when the app is
  brought back to the foreground.

Only changes to the shell itself (anything under `ios/`, `app/`, or
`capacitor.config.json`) need a new App Store build, and those are rare.

## How the pieces fit

| Path | What it is |
|---|---|
| `capacitor.config.json` | App ID `com.socialupgrades.clienthub`, the remote URL, splash and status-bar settings. |
| `ios/App/` | The Xcode project. Generated by Capacitor, with the icon, splash, `Info.plist` strings and a shared build scheme committed. Plugins come in through Swift Package Manager (`ios/App/CapApp-SPM`), so there is no CocoaPods. |
| `app/www/` | The tiny bundled page set. `error.html` is what the app shows when the site cannot be reached. |
| `app/native/entry.js` | The glue that runs inside the app: safe-area padding, status-bar colour, refresh on resume, native file saving and external links. |
| `public/su-native.app.js` | `entry.js` bundled with the Capacitor runtime (`npm run build:native`). Served by the website, loaded only inside the app. Commit it after rebuilding. |
| `public/su-native.js` | A 15-line loader included by `index.html`. In a browser it finds no native bridge and returns. In the app it loads `su-native.app.js`. |
| `ios/fastlane/` | The `beta` lane: sign, archive, upload to TestFlight. |
| `.github/workflows/ios-testflight.yml` | Runs that lane on a Mac runner. |

The website does not know whether it is running inside the app. The one line
added to `index.html` is the `su-native.js` script tag, and everything that
file does on the web is return early.

### What the glue does inside the app

- Adds `viewport-fit=cover` and pads the login gate, the main column, the
  bottom tab bar and the More sheet by the device's safe-area insets, so
  nothing sits under the notch or the home indicator. On an iPad the sidebar
  gets the top inset instead.
- Sets the status bar to light text over the navy login gate and the tablet
  sidebar, dark text over the light phone layout, and re-checks when the gate
  appears or disappears.
- Turns the native "app became active" event into a window `focus` event,
  which the dashboard already uses to re-pull data.
- Intercepts `<a download>` clicks (the dashboard's file and CSV downloads),
  fetches the bytes into the app's cache and opens the iOS share sheet, which
  offers Save to Files, AirDrop, Mail and so on. A plain web view ignores
  download links.
- Opens `target="_blank"` and off-site links in the in-app Safari view, so
  the dashboard is never navigated away.
- A light haptic tick on the bottom tab bar.

## One-time setup

The pipeline needs six repository secrets. None of them is an Apple ID
password; sign-in is by API key and the certificate is supplied as a file.

| Secret | Where it comes from |
|---|---|
| `APPLE_TEAM_ID` | developer.apple.com → Membership details → Team ID (10 characters). |
| `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_BASE64` | App Store Connect → Users and Access → Integrations → App Store Connect API → Team Keys → **Generate API Key** with the **App Manager** role. Download the `.p8` once (it cannot be downloaded again). Issuer ID and Key ID are shown on that page. `ASC_KEY_P8_BASE64` is the file base64-encoded: `base64 -i AuthKey_XXXX.p8 | pbcopy`. |
| `IOS_DIST_CERT_P12_BASE64`, `IOS_DIST_CERT_PASSWORD` | On the Mac that holds the Apple Distribution certificate used for the existing app: Keychain Access → My Certificates → right-click the *Apple Distribution: …* certificate → Export → `.p12`, choose a password. Then `base64 -i dist.p12 \| pbcopy`. If no distribution certificate exists yet, Xcode → Settings → Accounts → Manage Certificates → **+** → Apple Distribution creates one. |

Add them under GitHub → repository → Settings → Secrets and variables →
Actions.

The lane also tries to register the bundle ID and create the App Store Connect
record itself. If the API key is not allowed to, create them by hand: App
Store Connect → My Apps → **+** → New App, platform iOS, bundle ID
`com.socialupgrades.clienthub`, SKU `SU-CLIENT-HUB`.

## Releasing

A build goes to TestFlight when a tag `ios-v<version>` is pushed, or when the
workflow is run from the Actions tab:

```
git tag ios-v1.0.0 && git push origin ios-v1.0.0
```

The marketing version comes from the tag; the build number is the workflow
run number, so every build is newer than the last. The `.ipa` and the Xcode
logs are kept as a workflow artifact.

From TestFlight, App Store Connect → the app → Distribution lets you pick a
build, fill in the listing and submit for review. The listing, screenshots and
privacy answers are a separate step; the build is the same one.

### Building on a Mac instead

```
npm ci
npx cap sync ios
npx cap open ios        # opens ios/App/App.xcodeproj in Xcode
```

Xcode's own Archive → Distribute works with automatic signing once the team is
selected in Signing & Capabilities. The fastlane lane runs locally too with
the same environment variables exported.

## Changing the shell

- **Native glue** lives in `app/native/entry.js`. After editing, run
  `npm run build:native` and commit `public/su-native.app.js`. Deploying the
  website is all it takes for installed apps to pick the change up.
- **Capacitor config, icon, splash, plist strings** live under
  `capacitor.config.json` and `ios/App/App/`. These need a new build.
- **New Capacitor plugin**: `npm i @capacitor/<plugin>`, `npx cap sync ios`,
  import and use it from `entry.js`, rebuild the bundle, then a new build.

## Not yet done

- **Push notifications.** The `@capacitor/push-notifications` plugin is
  installed and the App Store Connect record is created with the push
  capability on, but nothing registers a device token yet. That needs an
  APNs key (developer.apple.com → Keys → **+** → Apple Push Notifications
  service), a `device_tokens` table, an edge function that sends a push when a
  `log` row is written for someone, and a few lines in `entry.js` to register
  and store the token after sign-in.
- **Face ID.** The `NSFaceIDUsageDescription` string is in place; the plugin
  and the unlock flow are not.
- **Universal links**, so that invitation and password-reset emails open in
  the app rather than Safari. Needs an `apple-app-site-association` file on
  the website and the Associated Domains capability.
